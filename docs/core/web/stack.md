# The standard website stack

One stack for every marketing site, so a fix learned on one site applies to all of them.
Exceptions get a line in that repo's `docs/DECISIONS.md`.

**Where the sites are today:** `nc-website` is on this stack. `basscats` is still plain HTML,
and its own `AGENTS.md` already says it is moving to Next.js when its magazine viewer needs it.
Nothing to change there now. PoP, PR2, and p3 start on this stack.

## Code

- **Next.js** (App Router, TypeScript), on the **same version as `nc-website`** (14.2 today).
  Upgrade all sites together, not one at a time.
- **Tailwind CSS**, with every color and font coming from the token roles in
  [`style-guide.md`](style-guide.md) (CSS custom properties, mapped in `tailwind.config`). No raw
  hex values in components.
- **Icons:** Phosphor (`@phosphor-icons/react`) only.
- **Fonts:** loaded with `next/font`.
- **Content lives in data files**, one per page (`content/home.ts` and so on), separate from
  layout. A copy change never needs to touch a component.
- **Images:** small ones in `public/`, large media (video, PDFs) in Vercel Blob, never in git.
- **No CMS** for now. Copy is edited in the content files, with Claude. `⚠️ open:` revisit if
  someone other than Paul or Jas needs to edit copy.

## Hosting

- One **Vercel project per site.** Every push to `main` goes live; branches get preview URLs.
- `www.` is canonical; the bare domain redirects to it.
- Domain and DNS changes are Paul's call. When moving DNS, keep every email record (MX, SPF,
  DKIM, DMARC) exactly as it is; see [`launch-checklist.md`](launch-checklist.md).

## HubSpot: forms, meetings, tracking

All our sites use **one HubSpot portal**, and the sending domains are connected there.

- **Forms:** HubSpot's form embed, styled with the site's tokens. Every form has a hidden
  **Brand** field set to the site's brand, so one CRM can sort leads per brand.
- **Meetings:** the HubSpot meetings embed, or a link to it, after a form where the flow needs it.
- **Tracking:** the HubSpot tracking code, one portal across all domains. `⚠️ open:` a cookie
  banner and the privacy policy wording to match it.
- Each site lists its form IDs and meetings link in its `AGENTS.md`.
- **Client sites use the client's portal,** never ours.

## Redirects

- Every old URL either still works or redirects. They live in `next.config.js`.
- Old marketing URLs on a domain we keep get **permanent** redirects (308).
- Links that point into the Neocreo app stay **temporary** (307), because the app host can change.
  See `nc-website`'s `next.config.js` for that pattern.

## SEO and sharing basics

- Every page has its own title and description.
- One share image (Open Graph) per site at least, per page where it matters.
- `sitemap.xml` and `robots.txt` generated by Next.
- No duplicate pages: one privacy policy, not two.

## Accessibility floor

- One `h1` per page; headings in order.
- Text contrast passes WCAG AA against its background.
- Everything works with a keyboard, with a visible focus ring.
- Motion respects "reduce motion".

## Before every push

- Run `npm run build`; it is what Vercel runs. Stop the dev server first.
- `/copy-pass` on changed copy.
- `/safe-push` to push. Then open the live page and look for the change
  ([`../rules/verification.md`](../rules/verification.md)).
- No new dependencies or paid services without asking.
